# Spotule — Data Model

All tables live in PostgreSQL 16. Models: `backend/app/models/*.py` (SQLAlchemy 2.0 typed
mappings). Migration: `backend/alembic/versions/0001_initial_schema.py` (autogenerated and
verified against the models; upgrade → downgrade → upgrade cycle tested).

```
                              ┌──────────────┐
                              │    users     │  tenant root
                              └──────┬───────┘
      ┌──────────────┬───────────────┼────────────────┬──────────────┬─────────────┐
      ▼              ▼               ▼                ▼              ▼             ▼
spotify_credentials user_preferences streams     banned_genres  automation_jobs  import_jobs
  (encrypted)        (locale, tz,     (ledger)    banned_artists  tool_runs        milestones
                      flags, JSONB)     │         blacklist_exemptions            friend_links
                                        │         skip_events · purge_runs        playlist_backups
                                        ▼         user_playlists
                       ┌────────── tracks ──────────┐
                       ▼            │               ▼
                    albums     track_artists      audio_features
                       │            ▼
                       └──────── artists ──── artist_genres ──── genres
                                                   (shared catalogue, not tenant-scoped)
```

## Tenancy

| Table | PK | Notes |
|---|---|---|
| `users` | uuid | `spotify_id` unique; `product` (premium/free) gates playback control; `role` member/admin |
| `spotify_credentials` | user_id | `access_token_enc`, `refresh_token_enc` (Fernet), `scopes`, `expires_at`, `revoked_at` |
| `user_preferences` | user_id | `locale` (en/fr), `timezone`, `skip_guard_enabled`, `stream_logger_enabled`, `share_stats_with_friends`, `share_stats_globally`, `settings` JSONB |
| `friend_links` | uuid | (user_id, friend_user_id) unique; `status` pending/accepted/blocked |

## Catalogue (shared, keyed by Spotify IDs)

| Table | Purpose |
|---|---|
| `artists` | name, image, popularity, followers, `fetched_at` (NULL ⇒ genres not yet hydrated) |
| `genres` / `artist_genres` | normalised lower-cased genre names; powers Top Genres and the Ban-Hammer |
| `albums` | name, type, release_date, image, `primary_artist_id` |
| `tracks` | name, `album_id`, `duration_ms`, explicit, popularity, `isrc` (cross-service matching), `is_local` |
| `track_artists` | ordered (position 0 = primary artist) |
| `audio_features` | tempo, energy, valence, danceability, acousticness…; `source` enum (spotify / reccobeats / acousticbrainz / user_import) |

## Streams — the lifetime ledger

`streams` (BIGSERIAL) is append-only. Columns:

* `user_id`, `played_at` (tz-aware), `spotify_track_uri`, `track_id` (nullable FK, attached
  after catalogue hydration), `ms_played` (NULL for API polls), `source` enum
  (`api_poll` / `json_import` / `web_sdk` / `skip_guard`)
* denormalised `track_name`, `artist_name`, `album_name` (imports, podcasts, deleted content)
* `context_uri`, `context_type` (which playlist/album/radio it came from)
* extended-history signals: `platform`, `country`, `reason_start`, `reason_end`, `shuffle`,
  `skipped`, `offline`, `incognito`

Constraints/indexes: `uq_stream_dedupe (user_id, played_at, spotify_track_uri)`,
`ix_streams_user_played (user_id, played_at)`, `ix_streams_user_track`, `ix_streams_user_source`.
A play "counts" as a stream when `ms_played IS NULL OR ms_played >= 30000` (Spotify's rule).

Supporting tables:

* `stream_hourly_rollups (user_id, bucket_start)` — streams / ms / unique tracks per UTC hour;
  the API rotates into the user's timezone for the listening clock.
* `sync_cursors (user_id, kind)` — `after` cursor for recently-played, error counters.

## Playlists

| Table | Purpose |
|---|---|
| `playlists` | mirror of Spotify playlist metadata; `managed_by_spotule` flags outputs of tools |
| `user_playlists` | tenant edge (owner/follower), pins, tags |
| `playlist_tracks` | ordered items (`track_uri` keeps local files representable) |
| `playlist_backups` | immutable ordered `track_uris[]` snapshot; `kind` (discover_weekly / release_radar / manual / pre_purge / pre_bulk); `week_label`; optional `materialized_playlist_id` |

## Ban-Hammer

| Table | Purpose |
|---|---|
| `banned_genres` | `pattern` + `match_mode` (contains / exact / regex), `apply_skip_guard`, `apply_library_purge`; unique per (user, pattern, mode) |
| `banned_artists` | explicit artist bans |
| `blacklist_exemptions` | allow-list overrides by artist / album / track |
| `skip_events` | audit: track, matched rule/genre, device, `detected_at`, `skipped_at`, `latency_ms`, success/error |
| `purge_runs` | dry-run or real; scanned/matched/removed counts, JSONB report, `backup_id` |

## Automation & audit

| Table | Purpose |
|---|---|
| `automation_jobs` | per-user recurring definition: `kind`, `cron`, `enabled`, `config` JSONB, last/next run |
| `tool_runs` | one row per tool execution (manual or automated): `tool_key`, `params`, `progress`, `result`, `backup_id`, `celery_task_id`, status/error |
| `import_jobs` | ZIP upload lifecycle + row counters + date range |
| `milestones` | (user, kind, threshold, entity_id) unique — achieved once, ever |

## Retention & scale notes

* `streams` at 1 M rows ≈ 250 MB with indexes; partition by `user_id` hash or by month once a
  tenant exceeds ~20 M rows (`PARTITION BY RANGE (played_at)` is a drop-in later).
* Hot analytics are cached in Redis for 10 min per (user, params); rollups make the clock O(hours).
* Catalogue rows are never deleted; users are (`ON DELETE CASCADE` wipes all tenant rows).
